# 裂变素材 vs 参考池：信息密度与范式对比

> 日期：2026-10-20
> 对象：`variant_contract.mp4`（新契约版）、`variant_01..05.mp4`（旧链路）
> 参考：5 条文胸案例 + 1 条个体带货案例（bd6f）
> 方法：切点/帧间运动指标 + 抽帧 + 逐条拆卖点/证据/字幕/口播/CTA
> 抽帧：`data/fission_slices/slice-1471-direction1/contact_sheets/`（本地）

## 0. 结论

你感觉到的“复古、像早一套宣传片”，不是帧间运动不足，而是：

1. **范式错了**：生成片是“品牌产品说明片/TVC”，参考池里真正像抖音个体带货的是“真人 + 口播 + 字幕 + 痛点/证明/价格/多场景”。
2. **信息层被主动删掉了**：当前契约明确禁止口播、字幕、真人、背景道具，并把 transcript/platform 标记为 waived；只保留商品结构视觉。
3. **信息类型单一**：生成片只有“商品结构事实”，没有明确卖点主张、使用场景、人物信任、价格/优惠、社会证明。
4. **切点多 ≠ 信息多**：生成片切点密度 20 次/分，高于 32b0（14.9）、1471（9.9）、15b4（4.5），但每次切镜只换了产品角度，没有换信息。

一句话：**它不是一个“信息更密的带货视频”，而是一个“拍得很干净的静物产品演示”。**

关键差异不是“卖点数量”本身，而是 **信息类型**：

- 参考片：`主张 + 证据 + 场景 + 人物 + 文字/口播 + CTA` 至少覆盖 4 类；
- 生成片：只有 `商品结构事实` 一类；没有主张句、没有场景、没有人物、没有文字/口播、没有 CTA。

## 4. 范式对比：品牌 TVC vs 抖音个体带货

| 维度 | 品牌 TVC / 产品说明 | 抖音个体带货 / UGC | 生成片 |
|---|---|---|---|
| 人物 | 无 / 手模 | 真人出镜、直接对话 | 仅手部 |
| 场景 | 纯白影棚、单一布景 | 家/办公室/多场景 | 纯白台面 |
| 信息 | 产品结构、材质、品牌调性 | 痛点、卖点、证明、价格、场景 | 只有结构 |
| 文字 | 无字幕或品牌字 | 大字号口语字幕、贴纸 | 无 |
| 声音 | BGM / 无口播 | 口播 + 环境声 + BGM | 环境底噪/BGM |
| 镜头 | 固定、对称、浅景深 | 手持、跳切、近景 | 固定俯拍、浅景深 |
| 转化 | 品牌记忆 | 价格/优惠/CTA | 无 |

生成片完全落在左列。参考池里：
- **bd6f** 是最典型的个体带货：办公室桌面拆包、真人对着镜头说话、大字幕、包装信息、面料特写；
- **32b0 / b27a / 84e9** 是模特种草：真人 + 字幕 + 多场景/多色 + 口播；
- **1471 / 15b4** 是长口播产品说明：视觉静态，但口播和字幕承载了 10+ 个卖点。

当前裂变链路用 1471 的画面风格 + 1471 的结构，但把 1471 唯一的信息载体（口播/字幕）删掉了，所以得到的是“1471 的静物版”，比 1471 更空。

## 5. 提示词偏好审计

当前 contract / prompt 里的原话：

| 位置 | 原话 | 效果 |
|---|---|---|
| `target.format` | `voiceover: false`, `subtitles: false` | 删掉口播和字幕 |
| `global.scene` | “纯白哑光台面，无背景道具；参考案例的纱帘、花艺、木质台面不迁移。” | 删掉场景信息 |
| `global.camera` | “固定机位为主……” | 锁死机位 |
| `global.person_policy` | “无真人出镜，仅手部入画……” | 删掉人物信任 |
| `global.audio_policy` | “无口播、无台词；只有环境底噪与 BGM。” | 删掉口播 |
| `global.text_policy` | “无字幕、无贴纸、无品牌 logo、无画面文字。” | 删掉文字信息 |
| `structure.concept` | “用‘手部动作节拍器’替代字幕节奏……无字幕无口播，全靠动作切点推进。” | **用动作替代信息** |
| `facet_coverage.waived` | transcript / platform / 字幕 / CTA 全部 waived | 信息层被显式放弃 |
| 负面约束 | “无口播；无字幕；无文字；无品牌logo；无真人出镜（仅手部入画）……” | 再次强化 |

这不是“描述不够细”，而是**契约主动选择了品牌产品演示的范式**。所以 H3 执行得越准确，越像一支“拍得很干净的老式产品宣传片”。

另一个偏好是时长/信息预算：12 秒 5 个 beat，每 beat 2–2.5 秒，只够放 4 个结构事实。参考 32b0 在 12.1 秒里塞了 7 个卖点 + 6 条文案 + 真人 + 多色；信息密度差在预算层面就已经注定。

## 6. 根因

1. **范式选择错误**：目标要“抖音个体带货”，契约却是“品牌 TVC/产品说明”。这是最大的偏好。
2. **信息层没有进契约**：facet 里有 transcript、on_screen_text、roles.marketing、structure.proof/cta，但 contract 只有视觉字段；transcript/platform 还被 waived。
3. **方向设计主动去信息**：“指尖倒计时”用动作替代字幕/口播，天然只承载结构事实，不承载主张、场景、价格、信任。
4. **评估指标只看商品**：`validate_output()` 只校验 identity/color/detail，9/9/9 通过；没有任何“信息密度/卖点覆盖/人物/字幕/CTA”校验，所以空信息片也能满分。
5. **池子里有范式样本但没被选中**：bd6f/32b0/b27a/84e9 都在池里，检索/泛化/方向生成却落到了 1471 的静物说明范式。

## 7. 建议：信息契约 v1

### 7.1 先选范式，再写分镜

在 contract 顶层加：

```json
"format_archetype": "ugc_individual_seller | model_seeding | brand_tvc | product_demo"
```

当前这条应标注为 `product_demo`；如果目标是抖音个体带货，必须选 `ugc_individual_seller`，并允许人物、口播、字幕、场景、价格。

### 7.2 每个 beat 增加信息槽位

```json
{
  "index": 1,
  "time": [0, 2],
  "claim": "小胸也能穿出自然聚拢",
  "proof": "真人举手，内衣不位移",
  "text_overlay": "小胸也能穿出自然聚拢",
  "voiceover": "小胸的姐妹，不要再穿钢圈了",
  "persona": "真人模特正面出镜",
  "context": "卧室/通勤前",
  "offer_cta": "",
  "visual_change": "真人全景 → 产品特写"
}
```

### 7.3 信息密度预算

以 12 秒个体带货为例：

| 维度 | 最低预算 |
|---|---:|
| 明确卖点主张 | ≥5 |
| 证明实验/对比 | ≥3 |
| 字幕或口播信息单元 | ≥5 |
| 人物出镜 | ≥1 |
| 场景/造型变化 | ≥2 |
| 价格/优惠/CTA | ≥1（带货） |

低于预算的 contract 要么判 `product_demo`，要么拒绝进入 `ugc_individual_seller`。

### 7.4 重新抽取 facet 的信息层

从现有数据可以直接抽：
- `transcript` → 口播行 + 时间；
- `shots[].on_screen_text` → 字幕行；
- `roles.marketing` → 卖点顺序/证明方式/CTA；
- `blueprint.structure.proof/cta` → 证明与转化；
- `shots[].subject/action` → 人物/动作；
- `global.scene` → 场景。

不要再把 transcript/platform 当 waived；它们是信息密度的主来源。

### 7.5 评估也要看信息

在 `validate_output()` 之外增加：
- `claims_covered`：contract 的卖点是否在成片中出现；
- `text_coverage`：字幕/贴纸是否出现；
- `persona_present`：真人/口播是否出现；
- `proof_count`：证明镜头数；
- `cta_present`：价格/CTA 是否出现；
- `information_density`：信息单元/10s。

## 8. 下一步建议

先做一条**个体带货范式**的垂直切片，用 `bd6f`（真人 + 口播 + 字幕 + 拆包）和 `32b0`（真人 + 多色 + 字幕）做结构参考，而不是继续用 1471 的静物说明：

- 方向：真人出镜口播，12 秒，6 个信息单元（痛点 → 产品 → 材质 → 结构 → 多色/场景 → 价格/CTA）；
- 必含：真人、口播/字幕、3 个证明、2 个场景变化、1 个价格/CTA；
- 产出后与 `variant_contract.mp4` 和 `bd6f` 做三方对比。

如果这个方向成立，再把 `format_archetype` + `information` 槽位写进 facet/contract 的 v1 schema，批量替换当前“产品说明片”默认值。
